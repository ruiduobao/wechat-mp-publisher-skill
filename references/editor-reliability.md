# 编辑器现场规则与验收

## 普通长文与图片消息

正文使用 `.rich_media_content .ProseMirror`。页面里还可能有标题、摘要的 ProseMirror，不能用全页 `.ProseMirror` 或 `[contenteditable]` 兜底。图片轮播消息会保留隐藏的长文编辑器，其占位符不表示真实文章为空。

`editor-mode.ts` 在任何标题、作者、正文修改前检查可见性和可编辑性，等待异步初始化；明确图片消息或隐藏正文则停止。遇到这种情况，先只读查看完整草稿索引的标题、摘要及正文身份，查找已有普通长文。候选确认后锁下更新映射，保留原图片稿 ID 的证据。没有可用长文时报告不支持，不能靠强改 CSS 或隐藏类型完成。

## 聚焦和正文注入

- 激活本任务标签，滚动到正文开头，在正文与当前视口的交集内点击。
- 文章高度可以远大于视口。`scrollIntoView({block:'center'})` 后按整个长文矩形中心/左上偏移计算点击位置，可能得到负坐标，导致永远无法聚焦。以视口内实际命中的正文区域为准。
- 选区必须位于准确的正文节点内。完整正文通过任务自有空白标签原生复制 HTML，向正文选区派发原生粘贴键；检查微信收到可信 HTML 粘贴事件，且粘贴后正文文本与准备内容一致。
- 原生粘贴时一并放入完整原题 H1，避免 `execCommand('insertHTML')` 继承旧首段标题格式。合成 ClipboardEvent 被取消也不能证明模型已正确接收。不得用正文 `innerHTML`、直接删 DOM 或无条件 true 冒充持久化成功。
- 外题/作者不应被正文全选操作改变。保存前再次核查首位唯一 H1 与完整原题。

## 图片和封面

本地正文图逐张上传，先定位本次占位符，等待选区同步并核对选择文本，再通过 Input.insertText 建立唯一文字标记。替换前后完整正文文本须只差这一个占位符到标记的替换；原占位符仍在就失败，不能直接给文字节点 textContent 赋值清理。之后检查准确位置新增的图片节点。微信会将图片放到标记段落的相邻独立 section；仅检查标记 span 的兄弟会漏检。检查本段或紧邻的无正文图片块，不使用全局最后一张图兜底。必须为已加载的微信 CDN 图片。

上传后精确选中标记，等待编辑器同步选区，再用原生退格删除，并验证确实消失。立即设选区就按键会与模型的异步选区更新竞争，使标记再次出现在保存稿。相同文件引用多次，按每次出现的位置分别处理。保存前再次拦截全部占位符与定位标记。

独立重开后等待图片加载。微信会把同一素材的 URL 尺寸段从 `/0` 改成 `/640`；比较时仅规范化合法 qpic 域名这两个尺寸，保留素材路径、其它参数与图片顺序。不能因为 URL 字符串不同就重传，也不能只凭总数相等放行。

封面独立于正文图片数：

1. 已有有效封面直接复用。
2. 从正文选图时单次点击遮罩，确认所选状态，再等“下一步”启用。
3. 从文件上传时锁定可见“选择图片”弹窗内文件控件。图库会复用相同素材，所以条目数不增加不能判失败；所选条目的实际文件名必须与本次文件匹配，排除无关旧选中项。
4. 缩略图可能是子节点 `i.weui-desktop-img-picker__img-thumb` 的背景，不能只找 `img`。
5. 在可见“编辑封面”弹窗中选择启用的 primary“确认”，派发一次 mousedown → mouseup → click；不能再额外 click 造成反选或重复提交。等弹窗关闭并读到真实封面 URL。
6. 保存后独立标签重开验证封面仍保留。

正文无图片的文章可以使用独立封面文件。私有 `cover-overrides.json` 是 `articleId -> 绝对图片路径`，引擎自动读取，没有 `--covers` 参数。当地封面生成器默认扫描当前源文件，不能依赖固定的旧清单。

## 原生名片

正文末尾必须是真正的 `mp-common-profile`，昵称和 `data-id` 与账号私有配置一致。优先复用从已验证草稿采集的真实原生模板，要求编辑器事务接受插入；无模板时走官方工具栏搜索并精确识别账号。简介提到旧名称不等于账号昵称是旧号，不能误杀正确账号。

名片外层可以是 section。检查其后不能有实质正文或媒体，允许尾部空段和编辑器 separator。仿制 div、仅名片对话框里选中了账号、直接 appendChild 都不能替代保存持久化证据。

## 保存与独立重开

保存后立即记录已有/新取得的 appmsgid 为 `saved-unverified`。随后关闭本任务编辑标签，另开独立任务标签从服务器读取同一 ID，等正文与媒体加载后检查 H1、外题、作者、封面、正确原生名片和图片集合。

保存回包为辅助证据，toast 或 URL 里本来存在 ID 不能算成功。重开检查失败就保留未验收状态。元数据修补不更新 appliedFingerprint；只有完整正文及图片真正应用且通过复验才晋升。
