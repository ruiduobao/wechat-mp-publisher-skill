# 日常操作手册

本手册适用于保存和更新微信公众号普通长文草稿。执行边界是草稿箱；最终发表、群发及通知关注者不在本技能范围内。

## 1. 确认代码与运行环境

在仓库根目录执行下面的命令。Windows PowerShell 和 Git Bash 均建议给含空格的路径加引号。

```bash
node --version
bun --version
bun install --frozen-lockfile
node bin/launch-publisher.mjs --help
```

Node.js 负责统一启动器，Bun 负责 TypeScript 运行时。正式写入前，启动器使用本仓库的 TypeScript 做类型检查。Bun 找不到时可设置 `WECHAT_BUN_PATH` 为实际可执行文件路径。其它路径与本机依赖见 [configuration.md](configuration.md)。

本机 `.agents/skills/wechat-mp-publisher` 与 `.zcode/skills/wechat-mp-publisher` 链接到同一代码库。修改仓库即可更新两处入口，不要再复制一套运行时。换设备时应先核对链接目标、私有配置与实际 CLI 帮助。

## 2. 只读预检与快捷检索

```bash
# 完整扫描，列出所有待处理项及缺标题文章的内容摘要
node bin/launch-publisher.mjs --check

# 按关键词快速定位特定文章（匹配 ID、文件名、标题或正文前3000字，含已 SKIP 项）
node bin/launch-publisher.mjs --check --search "GEM-15"

# 按批次与修改时间倒序，直接查看最新 N 篇（默认 1 篇）
node bin/launch-publisher.mjs --check --latest
```

预检比较当前 PC 可见的两个来源与私有状态库。它不写历史、基线或进程锁，也不连接浏览器。未连通的 Muse 远端可能还有未到达本机的文件，因此只报告 PC 当前索引。指定不存在的 `--id` 会报错退出码 1，不再当作“0任务”跳过。

文章身份为 `source:batch:prefix`，例如 `muse:20261112_0700:01`。微信数字 `appmsgid` 是草稿 ID，两者不要混用。日常用 `articleId` 选择文章，由状态引擎找到对应草稿。

动作的含义：

| 动作 | 执行含义 |
|---|---|
| `SKIP` | 当前状态及对应指纹已验收，无需编辑 |
| `CREATE` | 基线以外且没有既有草稿映射的新文章 |
| `CONTENT-UPDATE` | 从源文更新已有普通长文正文和图片 |
| `REPAIR` | 修补 H1、作者、外题、封面、名片，保留正文和原图 |
| `NEEDS-RECONCILE` | 身份或历史映射需要核对，不允许从零建稿 |

`needs-title` 表示缺少合规短标题，并不代表源文损坏。预检继续列出其它文章；正式执行前仍须为新文补齐短标题。不能缩短源文件里的完整原题来满足外题限制。

基线文件不存在时，当前来源会生成内存中的历史基线，当前已有文章先待核对；正式运行才受控持久化基线。这是为了避免重建用户原有草稿。首次安装不能把“0可执行”误当成所有文章已经保存，也不能盲目清空真实基线。确认是全新账号、全新来源时，应先在隔离测试路径验证配置，再建立经确认的初始映射/基线。

## 3. 准备外题与封面

按论文或事件的核心含义生成15字以内外题，字数按 Unicode 字符计算，英文、数字和连字符也计入。完整原题始终在正文首位 H1 保留。现有外题默认保持，明确发现错误时才指定新题。

私有标题映射示例：

```json
{
  "muse:20261112_0700:01": "全球野火年度遥感观察",
  "muse:20261112_0700:02": "海洋光合作用参数集"
}
```

该文件是 `articleId -> 短标题` 字典，不是草稿数字 ID 字典。推荐使用内置安全工具添加或更新短标题（自动核验 15 字上限、fail-closed 保护损坏 JSON、原子合并写盘，不丢失既有项）：

```bash
bun run titles "muse:20261113_1105:01=GEM-15全球15米高程模型"
bun run titles --list
```

也可以传入自定义 `--titles` 文件预检：

```bash
node bin/launch-publisher.mjs --check --titles "C:/private/titles-override.json"
```

正文无图也可以保存文章，但仍需要封面。处理顺序是复用已有有效封面、选择正文图，或上传独立封面文件。封面映射也是私有 `articleId -> 绝对图片路径` 字典，当前没有 `--covers` 参数。

本机私有 `generate-covers.py` 可以为零正文图文章生成文字封面。它不包含在公开仓库内，换设备需要另行准备生成器，或自己提供可用 PNG/JPEG 封面。不要把独立封面插进正文来充当正文图。

## 4. 单篇编辑

优先做小范围验证，再进行批量操作。

```bash
# 按状态选择更新或跳过
node bin/launch-publisher.mjs --id muse:20261112_0700:01 --title-override "全球野火年度遥感观察"

# 只修补特性，不重建正文
node bin/launch-publisher.mjs --repair --id muse:20261112_0700:01

# 明确按干净源文在原草稿重建完整内容
node bin/launch-publisher.mjs --refresh-content --id muse:20261112_0700:01
```

`--refresh-content` 需要已有草稿映射。旧基线缺映射时先核对真实草稿的论文、正文和图片，保留候选证据；不要删历史、清基线或另建替代稿。

图片轮播消息可能保留隐藏的普通长文编辑器。“从这里开始写正文”不等于线上稿件是空白。遇到 `unsupported-message-type` 停止该篇，保留其 ID 并报告，不改 CSS 或隐藏类型。

## 5. 批量操作

```bash
node bin/launch-publisher.mjs --titles "C:/private/titles-override.json"
```

可以按实际帮助中的 `--source`、`--batch`、`--days`、`--limit` 缩小处理范围。已有验收稿会跳过，单篇失败不代表其余篇未执行；看逐篇结果和末尾汇总。

复用宝玉路线的专用浏览器 Profile 与后台主页。按 Profile 查找调试端口，并使用 `/json/version` 返回的实际 WebSocket。若专用 Profile 尚无运行中的调试实例，引擎会以独立脱管进程安全拉起专用浏览器并等待就绪（绝不关闭或杀掉用户其它普通 Edge）。只关闭本任务创建的编辑、复制和复验标签。不要关闭用户标签或反复弹扫码图片。

登录失效时报告需要续期；模型服务商拒绝子 agent 请求与公众号登录失败是两件不同的事。

## 6. 保存与独立验收

每次保存都需要独立新标签从服务器打开同一草稿 ID，通过条件轮询等待标题、封面、正文图片与名片真正加载后检查：

1. 重开 ID 与保存 ID 相同。
2. 首元素为唯一完整原题 H1，作者和外题正确。
3. 正文文字与保存前一致，没有图片占位符、定位标记或本地图片路径。
4. 图片素材数量、顺序与加载均正常（`complete && naturalWidth > 0` 且为合法 qpic 域名）。
5. 封面 URL 实际有效，原生名片账号正确且居于正文末尾。

微信将同一合法 qpic 素材从 `/0` 显示尺寸改成 `/640` 时优先通过规范化 URL 比较；若微信服务端落库时因去重或重签名改变素材 URL 路径，则以 32×32 RGBA 内存像素交叉 MAE 验证各位置图片内容及顺序完全匹配，不放宽错图或乱序。

保存取得 ID 后先记录 `saved-unverified`。微信也可能自动保存新稿；失败重跑前应核对并保全已分配的 ID，避免重复创建。自动保存、toast 和回包均不能单独算验收通过。

元数据修补通过只推进特性修复记录。只有完整正文和图片真正保存并复验通过，才推进 `appliedFingerprint`。完整写入未验收时持久化 `pendingContentUpdate`；再次运行优先继续原 ID 的完整更新，显式 `--repair` 会提示需要完整重建。元数据修补不能清掉该待完成标记。

新稿自动保存取得 ID 后，先以候选证据保全，再独立核对身份；核对失败或超时也不会丢候选，下一次进入待核对而非重新新建。不要把“有 ID”“verified”“完整正文已应用”当成同一个统计量。

## 7. 报告与故障恢复

按本次开始时的任务集合统计：扫描来源数、唯一新增成功数、已有稿更新数、原有已验证跳过数、待核对、缺图、特殊消息类型、失败或未验收。相同新文先失败再修补通过，仍只算一篇新增成功，不能再算一篇独立更新资产。

详细诊断写私有报告，公开总结只给步骤、测试类别及实际结论。不要公开文章正文、账号模板、登录参数或状态映射。故障对照见 [troubleshooting.md](troubleshooting.md)，测试方法见 [testing.md](testing.md)。
